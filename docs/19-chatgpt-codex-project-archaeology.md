## Codex as an ATLAS subsystem

Codex should be treated as an engineering execution layer, not as ATLAS identity.

Proposed flow:

ATLAS / Ministries -> Engineering Mission -> ASAS Context Capsule -> Codex Engineering Agent -> tests / PR / review -> RIA -> merge

Codex responsibilities may include:
- implementation;
- refactors;
- test generation;
- migrations;
- CI/CD;
- documentation;
- repository maintenance;
- code review;
- dependency/security cleanup;
- prototype branches.

Boundaries:
- Codex does not alter ATLAS constitution on its own;
- privileged changes require review;
- all work occurs through branches/PRs;
- tests and rollback are mandatory;
- engineering results feed repository state, not epistemic truth automatically.

## New architectural insight

Across the historical projects, the recurring pattern is not one application but a family of operating systems:

- A+ OS -> organizational intelligence
- GeoMach OS -> domain/location intelligence
- NEXOR -> relational intelligence
- Kairos -> personal/presence intelligence
- Zaza -> cognitive/executive intelligence
- ATLAS -> unifying causal/personal/research intelligence

The strongest ATLAS direction is therefore to become the meta-operating system that can host or coordinate these domain intelligences without erasing their identities.

## Assimilation rule

Historical idea -> source verification -> formal model -> RIA -> implementation -> benchmark -> retain/reject

Conversation history is evidence of intent/design, not proof that a feature was fully implemented.
