# ATLAS Executive Network — Ministries, Agents and Cross-Cutting Governance

## Why this exists

ATLAS inherits the strongest organizational ideas from ZAZA/ASAS but does not copy the old architecture blindly. Ministries are modeled as **domain networks with explicit contracts**, not as free-running autonomous personas.

A ministry has:

- identity and mandate;
- domain ontology;
- skills;
- authorized tools;
- budget/limits;
- scoped memory;
- input/output contracts;
- dependencies;
- indicators;
- relationships;
- current context capsule;
- explicit agent roles.

These are attached to missions as deterministic controls before optional language-model agents are introduced.

## Default agent roles inside a ministry

### Lead
Frames the mission, owns the mandate and synthesizes final outputs.

### Researcher
Collects evidence, sources, models and candidate explanations.

### Analyst
Formalizes variables, compares scenarios and quantifies uncertainty.

### Critic
Searches for contradictions, failure modes and disconfirming evidence.

### Integrator
Translates outputs to other ministries and maintains context continuity.

Specialized roles may be added, but agents do not receive constitutional authority by default.

## Mission routing

A `Mission` declares required skills, domains, risk and action properties.

The deterministic `MinistryOrchestrator`:

1. matches skills to primary ministries;
2. attaches permanent governance bodies;
3. attaches context/simulation/math services when required;
4. exposes missing capabilities;
5. raises a human-approval requirement for external, irreversible or high-risk actions.

## Core rule

```text
specialized agents propose
deterministic services validate
cross-cutting bodies constrain
human approves sensitive actions
outcomes feed learning
```

## Integration with Operational Awareness

Every active ministry should eventually expose:

- health;
- queue depth;
- unresolved contradictions;
- confidence;
- blocked dependencies;
- recent errors;
- budget pressure;
- mission drift.

These signals become part of the ATLAS self-state.

## Integration with Context Capsules

Each ministry receives the same canonical mission capsule, then a domain-specific projection. This prevents each agent from inventing a different version of the mission.

## Integration with Voice

Voice should address the single ATLAS identity. The user should not need to call ministries manually.

Example:

> "Atlas, investigate whether this environmental pattern could affect sleep."

ATLAS may internally route the mission to:

- Health & Well-being
- Architecture & Environment
- Science, Traditions & Frontiers
- Mathematics & Coherence
- Epistemic Council
- Outcomes Observatory

The spoken answer is synthesized back into one coherent ATLAS response.

## Integration with internal science

Research & Evolution becomes the operational owner of the hypothesis backlog, while Science, Traditions & Frontiers maintains epistemic framing and Mathematics & Coherence provides formal tests.

## What is deliberately not implemented yet

- uncontrolled autonomous agents;
- direct self-modification;
- automatic external writes;
- automatic Git push;
- ministries operating without shared context;
- model outputs treated as evidence.

These require explicit contracts, tests and approval gates first.
